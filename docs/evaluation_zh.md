# 评测：隔离判断贡献，测量完整系统

[首页](../README_zh.md) · [English](evaluation.md)

任务或回合是基本评价单位。同一任务内的多次判断有诊断价值，却不是独立的成功率试验。同一场景派生多个任务时，也应保留这种相关性。

## 让对照对应研究问题

| 问题 | 固定什么 | 改变什么 | 报告什么 |
| --- | --- | --- | --- |
| Jev 是否更会选择？ | 状态、候选、执行器、任务 | 规则／结构化 LLM／Jev | 判断错误与完整任务结果 |
| 状态表示是否更好？ | 选择器、原始观察、任务 | 仅改变表示 | 信息缺失、判断与端到端影响 |
| 门控是否节省有效计算？ | 生成器、动作权限、评价 | 固定／规则／模型门控 | 成功、调用、门控开销、墙钟时间 |
| 预测是否有用？ | 候选、选择器、执行窗口 | 预测器或预测调度 | 后果忠实性、成功、风险、总计算 |

如果感知或控制同时变化，应标为系统对照。系统对照仍然有价值，但回答的问题不同。

## 最少需要记录的字段

| 类别 | 字段 |
| --- | --- |
| 身份 | 源码提交、SDK、请求模型、实际返回模型、渠道、运行日期 |
| 任务 | 任务定义、初态 ID、种子、扰动、成功与停止标准 |
| 输入 | 观测时间或版本、状态、候选定义、暴露给模型的真值 |
| 判断 | 所选项、可用概率、阈值统计量、回退、延迟 |
| 执行 | 实际动作、拒绝原因、观察后果、重试 |
| 结果 | 成败、原因、整局耗时、全部调用、用量与价格依据 |

保留失败与中断记录，区分完整新运行和续跑、缓存计划和在线规划、控制器动作和真实模型决策。重试同时计入时间与费用。

## 各方向的指标

**模型基础：** 准确率或任务分数、注明分箱方式的校准误差、适用时的 Brier 分数、选择性风险—覆盖率曲线、延迟分布与总用量。

**Agent 应用：** 最终完成、无效或过期目标、重试、关键事实误删、错误支持、观测年龄、完整任务耗时，以及辅助模型在内的总费用。

**具身智能：** 完整成功、扰动恢复、物体进展、接触丢失、碰撞、动作拒绝、过期动作执行、墙钟时间与全部感知／预测／决策开销。

优先报告成功—费用或风险—计算曲线，避免只挑有利阈值。基线应包括强规则和便宜的结构化模型，而不只是昂贵推理模型。

## 图像判断与定位

固定并记录原图、实际输入尺寸、旋转、裁剪坐标、编码／压缩、图像引用位置与请求头。比较候选集时尽量保持候选数量及题干不变；更换服务端点和图像编码的对照不能只归因于模型版本。

将正确候选缺失、错误前提、细节不可辨、图外信息和时间推断分开评测。添加“无法确定”也是修改候选定义，需要报告覆盖率与错误率。Box 记录 IoU、目标缺失时的误框率，以及 Noul 门控对存在／不存在目标的误拒绝／误接纳。重复调用和同图多题按图像聚类，不按答案数当作独立样本。

Visual Jev 等系统的同图多题 `ms/题` 是整批耗时除以题数。分别报告整批延迟、单题请求延迟、吞吐、冷／热缓存与峰值显存；训练准确率和共享计算收益分别对照。[多模态案例](multimodal_zh.md)与[社区模型](community-models_zh.md)提供具体例子。

## 时间与费用

顺序执行时，可以按以下阶段记账：

```text
感知 + 状态构造 + 预测 + 判断 + 执行 + 验证
```

异步系统的阶段会重叠，应直接测量墙钟时间并说明关键路径，不能把重叠时间相加当作总耗时。区分仿真时间、API 等待与视频播放；API 等待时物理暂停的试验，不能测量对持续运动世界的实时响应。

记录实际用量及对应日期、渠道的价格。模拟响应、缓存和免费额度应单独标明。昂贵请求变少，不自动意味着完整任务更快或更便宜。

## 数据划分与不确定性

在开发集选择提示、阈值与预算，在独立任务、布局、网站或扰动上冻结测试。尽量配对初态，同时报告成功数和百分比。在独立单位上 bootstrap，必要时按场景聚类。五个开发布局的结果，应一直保留这个样本量与开发集属性。

## 仿真器与世界模型

已知状态的分支仿真适合隔离选择和调度。学习型世界模型还要检查动作敏感性、失败预测、奖励一致性与误差累积，两类实验分开报告。用于评价的真值不能悄悄进入选择器输入。
