# 具身智能：判断、控制与物理反馈

[首页](../README_zh.md) · [English](embodied.md)

机器人判断需要经受接触、运动、延迟与不完整观察的检验。夹爪向目标移动不代表物体移动，命令完成也不代表任务推进。分析 Jev 时，应将其放回感知、预测、控制与反馈链路中。

## 决策接口与代表系统

具身应用可按决策粒度分为路点选择、技能评估、局部运动与动作复用。NavJev、Nav Arena、Stacker、jev-libero、EmbodiedJev、RoboJEV 和 RoboICL 分别展示了这些接口如何连接感知、预测和控制。

### 七个主要案例

| 案例 | 判断接口 | 物理或算法支持 | 证据范围 |
| --- | --- | --- | --- |
| [NavJev](https://arxiv.org/abs/2609.34969) | 根据动作相关描述选路点或停止 | 视觉前端与导航候选 | 百任务仿真对照与有限实机试验 |
| [Nav Arena](https://research.dimensional.org/system-one-navigation/) | 方向、转向、停止、完成与目标 | 结构化几何及导航系统 | 完整系统比较；多组样本应分开 |
| [Code Owns the Simulation](https://arxiv.org/abs/2610.01834) | 根据语言任务选技能 | 程序技能与已知物理模拟 | 动作粒度与控制辅助同时变化 |
| [jev-libero](https://github.com/Dimweaker/jev-libero) | 意图 → 类别 → 原子输入 | 27 种输入、分支仿真与几何计算 | 通过示例，不是完整基准成绩 |
| [EmbodiedJev](https://github.com/FBddcz/embodied-jev) | 局部方向与夹爪 | 视觉规划、RGB-D 处理和伺服 | 少量开发运行，包含失败 |
| [RoboJEV](https://github.com/lykycy123/RoboJEV) | 意图 → XYZ 与夹爪 | MuJoCo 状态、运动学与动作检查 | 作者整体评测中规则优于 Jev |
| [RoboICL 子实验](https://arxiv.org/html/2609.34261v1#S4.SS5) | 复用动作后缀或重新生成 | 独立动作生成器与执行记录 | 两项开发任务、各五个布局 |

## 按原始口径读取结果

以下是**引用来源中的作者报告结果**，不是本仓库新运行的实验。

| 案例 | 部分结果 | 必须随结论保留的条件 |
| --- | --- | --- |
| NavJev | Jev 27/100；GPT-4o 14/100；Qwen 25/100 | 相同输入接口；LLM 对照未启用推理 |
| Nav Arena | 短程子集 Jev 32/45，每次 0.055 美元 | 系统的软件不同；与 327 任务主评测分开 |
| Stacker | 技能选择 9/20；直接力矩 0/20；新指令 22/40 | 动作抽象与控制辅助不同；原任务规则为 8/20 |
| RoboJEV | Jev 43/50；规则 48/50 | 五项仿真任务，不是真机结果 |
| RoboICL 对齐方块 | 生成调用 181 → 121；成功 3/5 → 2/5 | 调用更少，同时完成任务更少 |
| RoboICL 物体拾取 | 生成调用 116 → 60；成功 4/5 → 5/5 | 小规模开发样本；还需计入门控开销与动作数 |

EmbodiedJev 的[所审阅 LIBERO 开发对照](https://github.com/FBddcz/embodied-jev/blob/main/docs/results/libero-vision/RESULTS.md)报告混合方案在抽屉样例中更快完成，但微波炉样例在预算内未完成。采用固定视觉目标或其他运行协议的演示，应与该对照分别评估。

## 与闭环 VLA 三个闭环的关系

| 闭环 | Jev 可能进入的位置 | 本索引已有证据 |
| --- | --- | --- |
| 执行闭环 | 判断继续、补充观察或重新生成 | RoboICL 动作复用、局部控制案例 |
| 预测闭环 | 选择候选后果，或决定是否调用预测 | 已知仿真器案例；学习型模型门控仍属设想 |
| 学习闭环 | 用累计结果更新策略、评价器、模型或接口 | 开放方向；推理时调用 Jev 本身不等于参数更新 |

[Awesome Closed-Loop VLA](https://github.com/ZJU-OmniAI/Awesome-Closed-Loop-VLA)提供执行、预测与学习的框架，[Awesome World Model](https://github.com/ZJU-OmniAI/Awesome-World-Model)提供世界模型概念与资料。

预测有两个不同接口。**预测之后**，Jev 可以选择候选，但无法节省已经完成的预测计算；**预测之前**，若仍有有效旧计划可执行，门控才可能减少调用。两种问题应独立实验。

[V-JEPA 2-AC](https://arxiv.org/abs/2506.09985)这类学习型潜空间预测器还引入新的接口问题：预测特征怎样转为选择器可消费的任务信息。该论文尚未验证与 Jev 的联合方案。

## 三个待验证实验

### 1. 执行纠错

固定抓取放置任务、生成器、控制器与感知，加入可重复滑落、目标移动或遮挡。比较固定执行长度、规则监控、快速结构化 LLM，以及由 Jev 选择继续／观察／重规划。

将**普通反馈／经观测验证的反馈**与**规则／Jev**交叉，区分信息改善与选择器改善。用未参与调参的扰动评测完整成功、恢复率、错误继续时长、不必要重规划、墙钟时间与总费用。

### 2. 主动观察

设置外形相似、任务属性不同的物体及可重复遮挡，固定检测器和候选视角。比较固定观察顺序、可见性或不确定性启发式、结构化 LLM 与 Jev 视角选择。

相同观察预算下，测量目标选择正确率与最终任务成功，计入额外运动与耗时。视觉前端从不估计的属性，不会因为多看一次就自动出现。

### 3. 按需预测

固定候选动作与预测后的排序方法，比较从不预测、每步预测、几何触发与 Jev 触发。先用已知仿真器隔离调度问题，再独立测试学习预测器。

同时报告成功或风险、总计算与墙钟时间；预测窗口必须覆盖实际执行窗口。仿真器调度的收益不能直接证明学习型世界模型可靠。

## 失败应进一步区分

- **状态失败：** 相关属性缺失或观察已经过期。
- **候选失败：** 提供的选项中没有能解决问题的动作。
- **判断失败：** 在已有可行选项中选了更差的方案。
- **执行失败：** 合理意图无法在动力学或约束下实现。
- **评价失败：** 成功判定或预测奖励本身错误。

先区分这些来源，再讨论模型贡献。用于评分的仿真真值，也应与决策器实际可见的信息分开。
